# Low Pressure 고장 기준 센서 추출 파이프라인 감사

모델을 학습하거나 기존 모델을 수정하지 않았다. 원본 고장 기록에서 `FlowCool Pressure Dropped Below Limit`의 고유 사건 **741건**을 확정하고, 각 사건의 `Tool / fault_event_id / fault timestamp / fault type`을 연결했다. 각 사건에서 24h·12h·6h·3h·1h·30m 전의 계산된 prediction timestamp를 만들었다. 총 **4,446개 사건×시점**을 검사했다. 이 시각들은 실제 미래 고장을 알고 계산한 **감사용 기준 시각**이며, 운영 중 예측 시각을 이렇게 선택할 수 있다는 뜻은 아니다.

## 시간 정렬과 누수 검증

모든 시각에서 `prediction = fault − horizon`이며 계산 TTF는 정확히 **24/12/6/3/1/0.5시간**이다. 입력 후보는 `prediction−30분`부터 `prediction`까지 실제로 기록된 9개 센서 행뿐이다. 직전 **모든 유형** 고장과 기존 시간 분할 경계를 넘어 센서 이력을 연결하지 않았다. 정지 구간 보간·가짜 행 생성은 하지 않았다.

자동 검사 결과 `last_sensor_timestamp > prediction_timestamp` **0건**, `last_sensor_timestamp ≥ fault_timestamp` **0건**, `prediction_timestamp ≥ fault_timestamp` **0건**이다. [전체 검사](leakage_check.csv), [오류 행](leakage_errors.csv).

원본 `train_ttf`는 *실제 센서 측정 시각*에 대응한다. 계산된 prediction timestamp에 정확히 관측이 없으면 단순히 `원본 TTF == fault−prediction`을 비교해서는 안 된다. `원본 TTF − (prediction−last_sensor_timestamp)`로 정렬하면, 센서 행이 있는 **2,189/2,189개 시점이 정확히 일치**했고 불일치 **0건**, 최대 차이 **0초**였다. 나머지 **2,257건은 해당 30분 창에 센서가 없어 비교 불가**이며 불일치로 세지 않았다. 원본 TTF·고장시각은 어떤 모델 feature에도 사용하지 않았다. [시점별 대조](ttf_consistency_check.csv).

## 실제 30분 이력과 고정 horizon coverage

기존 가용성 규칙을 그대로 적용했다: 실제 관측 60개 이상, 첫~마지막 시간 폭 24분 이상, 마지막 센서가 prediction timestamp에서 60초 이내, 9개 센서 모두 유한값. 이는 **연속 운전**을 보증하지 않으므로 gap 민감도는 따로 본다.

| 고장 전 시점 | 741건 중 사용 가능 | coverage | Tool 수 | Train / Validation / 예약·제외 |
|---|---:|---:|---:|---:|
| 24h | 132 | 17.8% | 15 | 92 / 25 / 15 |
| 12h | 168 | 22.7% | 18 | 117 / 32 / 19 |
| 6h | 205 | 27.7% | 16 | 136 / 48 / 21 |
| 3h | 204 | 27.5% | 16 | 138 / 45 / 21 |
| 1h | 317 | 42.8% | 16 | 178 / 86 / 53 |
| 30m | 304 | 41.0% | 18 | 186 / 73 / 45 |

이 수치는 이전 전체 유형 가용성 감사의 Train/Validation 고정 시점 수치와 일치한다. 전체 1,211건을 학습 대상으로 삼는 실험이라면 예약·제외 구간을 다시 섞지 않아야 한다. 이번은 원본 데이터의 741건 전체를 요구한 **읽기 전용 감사**이므로 예약 시기의 센서·TTF도 열었다. 그 부분을 앞으로 ‘미개봉 Test’라고 부르면 안 된다. [horizon별 표](horizon_coverage.csv), [설정](config.json).

## 이력 품질

전체 후보 4,446개 중 30분 창에 센서가 **하나 이상 있는 시점은 2,189개**, 기존 규칙까지 만족하는 것은 **1,330개**다. 사용 가능 창의 관측 행 수 중앙값은 **약 411개**, 관측 간격 중앙값은 **4초**, 실제 coverage 시간 중앙값은 **1,796초(29분 56초)**, 마지막 센서 지연 중앙값은 **2초**다. 하지만 최대 내부 gap 중앙값은 **90초**, p95는 **735초(12.2분)**이다.

품질 기준을 이번 결과에 맞춰 새로 고르지 않았다. 단순 민감도 계산으로 사용 가능 창 1,330개 중 최대 gap ≤5분은 **1,219개**, ≤90초는 **666개**다. `실제 coverage ≥20분`, `최소 60행`, `gap ≤5분` 등 개별 조건과 horizon별 분포는 [품질 요약](history_quality_summary.csv)과 [모든 창의 metadata](sensor_history_quality.csv)에 있다. 한 창에 많은 4초 행이 있어도 긴 정지 공백이 있을 수 있다.

## 사람이 확인할 5개 사건

센서 값을 보기 전에 Tool `01_M01`, `03_M02`, `06_M02`, `08_M01`, `09_M01`를 정하고, 각 Tool에서 기존 규칙으로 사용 가능한 horizon이 가장 많은 Low 사건을 선택했다(동률이면 가장 이른 사건). 고른 사건 ID는 **1, 304, 775, 856, 990**이다. 30개 사건×horizon 중 기존 기준 사용 가능은 **24개**, 원본 TTF 대조 가능은 **29개·모두 일치**다. 저장한 첫 3·마지막 3 센서 행 **174/174개**와 TTF **29/29개**를 원본 `data/train` CSV와 다시 대조해 모두 일치함을 확인했다. 예를 들어 `03_M02` 사건 304의 고장 timestamp는 **8,612,686**, 3h 전 prediction timestamp는 **8,601,886**이다. 마지막 실제 센서는 **8,601,884**에 있고 원본 TTF를 2초 보정하면 계산값 **10,800초**와 일치한다. 반대로 `01_M01` 사건 1의 3h 창에는 센서 298행이 있지만 마지막 관측이 예측 시점보다 **500초 오래돼** 사용 가능으로 세지 않았다. [수동 검증 30행](manual_validation_samples.csv), [각 창의 첫 3·마지막 3 원본 센서 행](manual_raw_rows/first_last_3_rows.csv), [원본 CSV 대조 요약](manual_source_summary.json).

## 고장까지의 센서 변화

분포는 파이프라인을 통과한 창의 **마지막 실제 센서값**을 사건당 horizon마다 한 값으로 요약했다. 각 센서의 mean/median/std/p25/p75는 [horizon별 분포](sensor_horizon_summary.csv)에 있다. horizon마다 포함되는 사건 집합이 달라 전체 평균만으로 변화 방향을 판단하지 않았다.

동일 사건에서 **24h와 30m 두 시점 모두** 가능한 사건은 **66건**이다. 그중 `FLOWCOOLPRESSURE` 마지막값은 **27건 증가 / 37건 감소 / 2건 동일**, `FLOWCOOLFLOWRATE`는 **32건 증가 / 31건 감소 / 3건 동일**이다. 압력 감소 방향이 약간 많지만 어느 쪽도 여러 사건에서 지배적인 패턴이 아니다. 6h→30m 짝은 99건, 1h→30m 짝은 238건이다. 관측된 시점이 3개 이상인 218사건에서 압력값이 전 구간에 걸쳐 단조 감소한 사건은 **34건**, 단조 증가 **25건**, 동일 **2건**이다. [고정 시점 쌍](paired_sensor_trends.csv), [사건 내부 방향](event_direction_summary.csv).

Tool별 방향도 다르다. 6h→30m 압력값은 `03_M02`에서 56건 중 감소 27·증가 28건으로 균형이고, `09_M01`은 15건 중 감소 5·증가 8건이다. 나머지 Tool 합계에서는 25건 중 감소 19건이지만, 이 집합은 여러 Tool을 합친 것이며 각 Tool 표본이 작다. `08_M01`은 짝이 3건뿐이다. 따라서 전체 평균의 압력 감소를 모든 설비의 일관된 열화 패턴이라고 해석할 수 없다. [Tool 그룹별 paired 비교](tool_group_paired_trends.csv).

## 판단

**데이터 추출 파이프라인은 의도한 시각 관계를 지킨다.** 실제 fault timestamp로 6개 prediction timestamp를 정확히 만들고, 그 이전의 실제 센서만 사용했으며, 2,189개 가능한 원본 TTF 비교에서 불일치와 미래 센서 누수는 0건이다. 다만 24h 전 사용 가능 사건은 132/741건뿐이고, 30분 이력이 있어도 긴 내부 공백이 남는 창이 있다. 이번 고정 시점·원본 센서 마지막값 분석에서는 Low Pressure 전 24h→30m 변화 방향이 사건과 Tool 전체에 일관되게 나타나지 않았다. 이전 Low 전용 RUL baseline도 사건 MAE가 Dummy 대비 0.62시간만 개선됐으므로, **같은 연속 TTF 회귀를 그대로 재시도할 근거는 약하다**. 다음 분석을 한다면 모델 복잡도를 높이기 전에 **Tool별 정상 기준 상대값과 관측 공백/가동 상태**에서 사건 내부 신호가 더 일관되는지를, 현재 시간 분할의 Train에서만 규칙을 정해 확인해야 한다.
