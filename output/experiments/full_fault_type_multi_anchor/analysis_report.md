# 다음 고장 유형 3분류: 실제 센서 다중 사전 시점 실험

## 범위와 데이터

실제 고장 사건 1,211건(Low 741, High 333, Leak 137)을 출발점으로 삼았다. 기존 Tool별 시간 분할을 유지하고 Train/Validation에 속하지 않는 사건은 쓰지 않았다. 각 사건 30분·1시간·3시간·6시간·12시간·24시간 전을 후보 시점으로 삼고, 그 시점까지 실제 기록된 직전 30분 센서만 사용했다. 중간 결측 구간을 채우지 않았다. 직전 고장 이후 및 해당 split 안에 있는 센서만 허용했다.

Strict는 30분 창 안의 유효 관측 60행 이상, 실제 관측 범위 24분 이상, 마지막 센서 관측의 나이 60초 이하다. Candidate A는 Tool별 Train 정상 4초 간격에서 기대한 450행 대비 50% 이상, 관측 범위 15분 이상, 마지막 관측 나이 5분 이하다. 두 규칙은 포함관계가 아니다. 9개 raw 센서의 현재값·평균·표준편차·최솟값·최댓값·중앙값·시간당 기울기·마지막값과 첫값의 차이, 총 72개 feature를 이전 단일 시점과 같은 수식으로 사용했다. 요청의 p25/p75는 이전 72개 정의에 없으므로 추가하지 않았다. 기존 30분 단일 시점 347건의 모든 feature와 값이 일치했다. Tool ID·horizon·TTF·fault 시각은 입력에서 제외했다.

| 조건 | Train 표본 / 사건 | Validation 표본 / 사건 | Validation Low / High / Leak 사건 | 사건당 평균 anchor |
|---|---:|---:|---:|---:|
| Strict | 1,121 / 449 | 396 / 173 | 140 / 24 / 9 | 2.29 |
| Candidate A | 1,293 / 476 | 460 / 182 | 148 / 25 / 9 | 2.53 |

각 horizon의 Low·High·Leak 표본/사건 수는 [anchor_counts.csv](anchor_counts.csv)에 모두 저장했다. 각 horizon에서 한 사건은 최대 한 표본이므로 그 표의 표본 수와 사건 수는 같다. Validation 총수는 Strict 30m/1h/3h/6h/12h/24h에 91/107/62/60/40/36, Candidate A에 95/125/76/68/52/44건이다. 기존 단일 시점 Validation은 Low 73, High 14, Leak 4건이었다. Candidate A 전체의 High 25, Leak 9건으로 **고유 사건도** 증가했으나, 460행을 460개의 독립 사건으로 해석하면 안 된다.

## 모델 및 검증

이전 Random Forest의 나무 300개, 최대 깊이 8, 최소 잎 크기 2, random_state 42를 고정했다. 사건별 anchor 수 N에 따라 각 Train 표본에 1/N 가중치를 부여했다. 별도 조건에서는 사건 기준 역빈도 class weight까지 곱했다. 모델 4개는 동일 Validation의 각 조건별 사용 가능한 사건에서 평가했다. Strict와 Candidate A의 평가 사건 집합은 다르므로 수치 차이를 순수한 센서 규칙 효과로 해석할 수 없다.

| 모델 | 행 단위 Macro F1 / BA | 사건 평균 score Macro F1 / BA | 사건 High recall | 사건 Leak recall |
|---|---:|---:|---:|---:|
| 기존 단일 30m RF | 0.603 / 0.611 | 0.603 / 0.611 | 6/14 = 42.9% | 2/4 = 50.0% |
| Strict, 사건 동일가중 | 0.556 / 0.506 | 0.458 / 0.451 | 1/24 = 4.2% | 3/9 = 33.3% |
| Strict, 사건+class 균형 | 0.677 / 0.768 | 0.694 / 0.843 | 20/24 = 83.3% | 8/9 = 88.9% |
| Candidate A, 사건 동일가중 | 0.579 / 0.523 | 0.443 / 0.427 | 2/25 = 8.0% | 2/9 = 22.2% |
| Candidate A, 사건+class 균형 | 0.680 / 0.800 | 0.705 / 0.851 | 21/25 = 84.0% | 8/9 = 88.9% |

BA는 Balanced Accuracy이다. 사건별 여러 anchor의 score 평균은 **사후 사건 집계**다. 미래에 아직 발생하지 않은 anchor를 기다렸다가 평균낼 수 없으므로 대시보드의 실시간 진단 성능으로 사용할 수 없다. Candidate A + class 균형의 단일 anchor 성능은 30m Macro F1 0.660/BA 0.831, 1h 0.692/0.852, 3h 0.646/0.750, 6h 0.752/0.786, 12h 0.734/0.813, 24h 0.636/0.725이다. 12h와 24h의 Validation 사건은 각각 52건과 44건, Leak는 4건과 3건에 불과하다. 이 숫자만으로 24시간 사전 진단이 안정적이라고 할 수 없다.

선택된 Candidate A + 사건·class 균형 모델의 사건 평균 score 기준 유형별 Precision/Recall/F1은 Low 0.968/0.824/0.891(148건), High 0.636/0.840/0.724(25건), Leak 0.348/0.889/0.500(9건)이다. **Leak로 진단한 23건 중 정답은 8건**이라서 88.9% 재현율만 보고 충분하다고 판단하면 안 된다. 행 단위 유형별 지표, 사건 집계 방식별 지표, 혼동행렬, 누적 horizon 지표는 별도 CSV에 있다.

같은 기존 30m 사건 집합으로 맞춰 비교하면 기존 RF의 Macro F1/BA 0.603/0.611 대비 새 Candidate A + class 균형의 마지막 anchor(주로 30m) 0.642/0.826, 사건 평균 0.659/0.850이다(공통 90건). 공통 Strict 91건에서는 각각 기존 0.603/0.611, 새 마지막 anchor 0.682/0.860, 사건 평균 0.665/0.870이다. 사건 집합과 학습 가중치가 함께 달라졌으므로 개선 원인을 multi-anchor **하나로만** 돌릴 수 없다. 이전 기본 RF는 사건 균형과 class 균형을 사용하지 않았다.

선택 모델의 행 단위 High→Low는 16/64, Leak→Low는 1/29이고, 사건 평균 score는 High→Low 4/25, Leak→Low 0/9다. 대신 Low→Leak가 15/148건으로 증가했다. 이전 단일 시점 혼동과 표본 수가 다른 점에 유의해야 한다.

RF 점수는 보정된 확률이 아니다. 선택 모델의 행 단위 최대 class score ≥0.5/0.6/0.7/0.8이면 coverage는 90.0/76.5/62.2/44.3%, 표시 표본은 414/352/286/204, 표시 중 정답률은 83.1/85.8/91.3/96.1%다. 사건 평균 score는 coverage 90.7/77.5/59.3/40.7%, 표시 사건 165/141/108/74건, 정답률 85.5/87.9/92.6/98.6%다. 높은 점수만 보이면 High/Leak 표시가 크게 줄어든다. 정확한 오답 수와 유형별 표시/정답 수는 [confidence_thresholds.csv](confidence_thresholds.csv)에 있다.

Validation Candidate A 182건 중 03_M02가 80건(44.0%)이다. 09_M02는 9건, 06_M02는 6건이다. 선택 모델의 사건 평균 score Macro F1은 전체 0.705, 03_M02 제외 0.666, 09_M02 제외 0.664, 06_M02 제외 0.709다. 각 Tool에서 실제 세 유형이 모두 있지 않은 경우 Tool별 Macro F1·BA는 불안정하거나 정의가 달라진다. 개별 Tool 숫자보다 Tool 제외 민감도를 우선 본다. 08_M01은 13건 중 정답 3건으로 큰 편차가 있다.

자동 검사에서 sensor timestamp > prediction timestamp, prediction timestamp ≥ fault timestamp, 동일 사건의 Train/Validation 중복, TTF·horizon·Tool·fault/target 입력, Reserved/Excluded 사용 모두 **0건**이었다. 이는 구현상 누수 검사 결과이지, 실제 운영 성능에 대한 보증이 아니다.

## 결론

이번 개발 Validation에서는 **사건·class 균형 가중치가 High/Leak 편향을 줄였고**, Candidate A가 Strict보다 사용 가능한 사건을 9건 늘렸다. 사건 평균 score 기준 차이는 Macro F1 +0.011, BA +0.008로 작으며 평가 모집단도 달라 Candidate A 자체가 우월하다고 확정할 수 없다. 기존 기본 RF 대비 성능 향상은 확인됐지만, 다중 anchor·class 가중·사건 가중의 효과가 한꺼번에 포함돼 있다. 특히 Leak 검증 사건 9건, 특정 Tool 편중, 실제 Model 1 경보 시점과 고장기준 고정 anchor의 불일치 때문에 이 모델을 곧바로 대시보드용 Model 2로 확정할 수준은 아니다.

다음 단일 실험은 저장된 Model 1 경보 시점 전체에서 선택 모델의 30분 실제 센서 이력 확보율과 Low/High/Leak 진단 성능을 **재학습 없이** 평가하는 것이다. 그 전까지 선택 모델 파일은 개발 후보로만 취급한다.
