# 24시간 XGBoost 기준 모델 재현 기록

AGENTS.md의 수치는 과거 실험의 기준값으로만 사용했다. 현재 저장소에는 그 수치를 생성한 24시간 코드, 모델 파일, 예측 점수 파일이 없다. 실제 `data/processed`의 20개 train 설비와 `fault_events.csv`로 새 모델을 학습했다. 기존 파일은 변경하거나 덮어쓰지 않았다.

## 남아 있는 코드와의 관계

- `src/train_xgboost_baseline.py`: 02_M01의 30분 단일 유형 실험. 고장 주기 그룹 분할과 음성 다운샘플링을 사용한다. 24시간 전체 설비 baseline의 직접 실행 파일은 아니다.
- `src/train_xgboost_4s_benchmark.py`: 설비별 시간 분할과 중단 처리에 가장 가까운 코드이지만, 4초·30/60/180분·다중 유형 모델이다.
- `src/evaluate_models_02_m01.py`: 30분 단일 설비 모델을 비교하고 학습 내부 교차검증으로 임계값을 정한다.
- `src/model_test.py`, `src/data_test.py`: 데이터 탐색용 코드이며 24시간 학습·검증 설정이 없다.

## 확인한 재현 설정

- 실제 원본 82,189,440행을 중복 측정까지 포함해 1분 특징 5,777,042행으로 집계했다.
- 다음 저압·고압·누출 고장 중 하나가 현재 시각부터 실제 시계 시간 86,400초 이내이면 1이다. 전체 기간을 관측할 수 있고 고장이 없으면 0, 아니면 검열한다.
- 설비별 앞 80%를 학습, 뒤 20%를 검증에 사용한다. 경계 앞 24시간을 학습에서 제거한다.
- 85개 현재·과거 센서/공정 특징을 사용한다. 원본 TTF, 고장 시각/유형, 절대 time, Lot, runnum은 입력에 사용하지 않는다.
- XGBoost 120개 트리, 최대 깊이 5, 학습률 0.05, 행/열 표본비율 각 0.8, 학습 정상/고장 비율의 `scale_pos_weight`, 시드 42를 적용했다. 임계값은 0.5다. 정확한 과거 하이퍼파라미터는 현재 저장소에서 확인할 수 없어 이 부분은 재구성한 값이다.
- 10분 오경보 사건은 정상 행에 난 경고를 설비별로 묶어, 직전 오경보와 600초보다 길게 떨어지면 새 사건으로 센다.

## 결과 및 원인 추적

검증 정상 1,074,774행, 고장 67,338행, 검열 13,303행은 기준 실험과 정확히 일치한다. 따라서 이번 점수 차이의 주된 원인은 원본 데이터 수, 24시간 라벨, 검증 분모 변경이 아니다. 학습·검증에 같은 고장 사건이 겹치지 않았고 학습 정답이 검증 경계를 넘은 경우도 0건이다.

정밀도 17.44%, 재현율 49.30%, F1 25.77%, 균형정확도 67.34%, AP 16.68%다. 혼동행렬은 TN 917,665 / FP 157,109 / FN 34,139 / TP 33,199이고, 10분 오경보 사건은 3,414건이다. 기준과 비교하면 FP 12,893건과 오경보 사건 638건이 적지만 TP도 901건 적다. 가장 가능성 높은 차이의 원천은 과거 24시간 코드에서 사용한 세부 특징 산식 또는 확인되지 않는 XGBoost 파라미터다. 검증 결과에 맞추어 파라미터를 조정하지 않았다.

기계가 읽을 수 있는 전체 설정·누수 검사·지표 차이는 `reproduction_report.json`, 표는 `metric_comparison.csv`에 있다.
